# WAL 积压与空闲连接重复观测优化

本次修复针对用户现场约 30 万条待确认观测、256 MiB WAL 接近满载，以及空闲连接每秒重复上报的问题。保留每秒本地采样、流量变化及时上报、现有设备身份与 WAL 文件格式，不通过清空缓存或扩大容量掩盖问题。

1. WAL 记录已确认记录的可回收字节；确认后释放对应内存，避免每批复制整个待发送队列。按可回收量整理文件，大积压不再每确认 500 条就重写整个文件；接近容量时按需回收已确认空间。整理使用缓冲写入。
2. 有待发送记录时连续补传，保持单批有界、逐批 ACK、心跳优先和严格序列校验。能力状态定期刷新，避免补传每批都写一次 PostgreSQL 设备状态。
3. Endpoint 与 conntrack 快照仍每秒采样。只省略完全无变化且无流量的快照，最长 10 秒保活；流量、速率归零、状态、进程/容器或其他元数据变化立即记录；DNS 和外部流导出事件不被去重。
4. 新协议为观测增加覆盖起点，并由 Center 握手声明支持。旧 Center 继续接收原先完整快照；新 Center 保留旧 Agent 语义。稀疏模式的 presence 按覆盖区间分配到分钟，保持字节增量及 flow_id 不变。采集失败、WAL 拒绝写入或采样中断后，不跨数据缺口推算持续时间。
5. 当前 WAL 状态与历史 data_gap 分别报告；恢复后 WAL 可以恢复正常，历史缺口仍保留。修正 Endpoint 连接关闭事件重复携带上次流量增量的问题。

验证：大 WAL 小批 ACK 不重写文件、满载空间回收、重启与 ACK 序列保持、10,000 空闲连接观测量下降、流量变化/关闭/归属变化不丢事件、分钟边界持续时间与字节不重复、旧 Center 降级兼容、断线补传与心跳。运行 Go 测试、race、vet 和 ARM64/ARMv7 编译。实际 NAS 是否还有网络或数据库错误，需结合 Agent 日志与更新后的 pending 趋势确认。

## 本地实施与验证记录

- 已实现上述优化；同时修正 conntrack 将累计包数与上次增量相减的问题，避免无新数据包时仍产生虚假增量。
- 10,000 条空闲连接连续采样 60 次，原本 600,000 条观测降为 60,000 条；第 61 次采样保活时，累计覆盖完整 60 秒，每条连接的 flow_id 保持不变。持续有流量的连接仍逐周期上报。
- 模拟 gRPC Center 验证 10,000 条 WAL 补传的批次顺序、逐批 ACK、配置消息不冒充 ACK，以及慢速 ACK 时心跳不被饿死；错误 ACK 不删除本地待确认数据。该测试不代表生产数据库吞吐。
- Go 全量测试、Agent/Store/Server race 检查通过；数据库注册集成测试因未设置 `POSTGRES_TEST_DSN` 跳过。大 WAL 回收、重启、旧协议、关闭尾段、分钟边界和采样抖动均有回归测试。
- 中英文 README 与中文运维文档已更新；安装脚本、Web 向导及 Compose 默认版本统一为 v0.3.31。未在用户 NAS 上升级原生 Agent，现场 WAL 排空效果仍待部署验证。
