# 远端 IP 归属、实时地球与多维排名设计

**日期：** 2026-11-17
**状态：** 设计已确认；归属、地球、24 小时排名实现中；连接发起方尚未实现
**范围：** Network Observer Center、PostgreSQL / ClickHouse、Vue 控制台

## 目标

在现有可用的 Agent 数据采集与 Center 上增加三类总览能力：

1. 对远端 IP 关联域名、ASN 登记组织和归属地，允许管理员修订元数据并标记可信。
2. 在网络总览展示可交互的 3D 点阵地球，并依据当前活动连接绘制可解释的实时路线。
3. 在总览提供最近 24 小时的流量与观测流数排名，覆盖 Agent、远端域名、Agent 本地端口和 Agent 进程，并允许切换其他维度。

继续使用现有 Center、PostgreSQL、ClickHouse、REST、WebSocket 和 Vue 应用，不引入独立分析服务。连接结束后仍不提供逐连接历史检索。

## 已确认的设计决策

- 手工元数据和可信状态以规范化后的远端 IP 为全局键，对所有 Agent 的观察结果生效。
- 域名优先级为手工域名覆盖、仍有效的 Agent DNS 关系、Center PTR 反查。保留来源与更新时间；多个 DNS 名称并存时保留歧义状态，不静默选成唯一事实。
- ASN、组织和地理位置继续使用 Center 本地 MMDB。每个字段可独立手工覆盖；界面同时保留自动来源，允许清除手工值以恢复自动值。
- PTR 只针对公网远端 IP，由 Center 异步执行、限速和缓存；PTR 仅作为域名线索，不替换 DNS 观察关系。查询失败、超时、私网或保留地址返回未知，不阻塞采集。不会将 IP 发往第三方反查 API。
- IP 的“可信”是独立标记，可在 IP 详情、连接和排名中显示并作为筛选条件；默认不隐藏可信 IP，不排除其流量，也不改变采集。
- 历史流量字节与分钟汇总保持只追加/既有 TTL 行为，不因手工编辑或新 GeoIP 数据而重写。历史查询在响应阶段按当前 IP 覆盖值显示标签；原始观测来源和自动值仍可查看。
- 24 小时连接数定义为查询窗内去重后的观测 `flow_id` 数，不是逐条会话归档，也不承诺等同于应用感知的会话数。Agent 维度计数以 Agent 与 flow ID 组合去重；按本地端口、进程、域名等维度统计时，同一 flow 可出现在多个维度桶中。
- 连接发起方是独立于上传/下载的语义。TCP 按证据标为“本机发起”“远端发起”或“未知”；Agent 启动前已存在或无法关联生命周期事件的连接标为未知。网关 conntrack 可确定原始方向，但只有端点相对本地网段的关系明确时才映射成本地/外部发起，否则保留未知。UDP 没有 TCP 式握手，只有观测到新流首个数据方向时显示“首次观察方向”；不能证明首次方向时标为未知。
- Lucky/CDN 的 `X-Forwarded-For` 不在本轮范围。网络层保留实际对端 IP；后续若 Lucky API 提供经可信代理链校验的客户端 IP，可作为单独的代理报告客户端元数据关联，不能改写网络五元组、上下行或字节归属。
- Agent 的地球起点由管理员为每个 Agent 手动设置可选经纬度。未设置时不画该 Agent 的路线；实时连接及排名仍正常显示。不使用 Center、网关出口或私网 IP GeoIP 冒充 Agent 位置。
- 地球终点使用远端 IP 的手工坐标（若填写）或 GeoIP 坐标。公网城市库坐标是近似地理归属，不代表设备精确位置；无坐标时不画路线。

## 元数据来源与展示

### 域名

对活动连接，以远端 IP 匹配 Agent 上报且处于 DNS TTL 有效期内的 DNS 关系；多个并行域名同时有效时标记为多个/歧义。历史流量优先使用当时已保存的域名快照。若未获得有效 DNS 名称，则对公网 IP 异步 PTR 反查，并缓存成功、无记录和临时失败状态，避免重复查询。

连接、IP 详情、排名行显示域名值、来源（手工、DNS 观察、PTR 或未知）、最近更新时间及歧义提示。PTR 结果不伪装成 Agent 观测到的 DNS 查询。

### ASN 与地理

继续使用 Center 管理和更新的 GeoLite MMDB，查询 ASN、登记组织、国家、地区、城市和坐标。应用字段级手工覆盖后返回最终展示值，同时保留数据库值、数据库版本和来源以便追溯。MaxMind 署名继续保留。

### 手工覆盖与 API

PostgreSQL 新增按规范化 IP 唯一键存储的手工覆盖表，字段包括显示域名、ASN、ASN 登记组织名、国家、地区、城市、纬度、经度、可信状态、更新时间和操作人。可空字段表示没有手工覆盖；清空字段即恢复自动来源。纬度范围为 -90..90，经度范围为 -180..180；地址必须是合法 IPv4 或 IPv6。

新增受管理员认证保护的写接口，使用请求体传递 IP，避免 IPv6 路径转义歧义：

- `PATCH /api/v1/ip-metadata`：更新某 IP 的字段级覆盖/可信标记；空值语义明确为清除对应覆盖。
- 扩展 `GET /api/v1/enrichment?ip=...`：返回自动字段、最终显示字段、来源、更新时间、可信状态、PTR 状态和未知原因；保持现有响应兼容。

每次新增、修改、清除覆盖或可信标记都写入现有 PostgreSQL 审计日志。写请求校验字段长度、地址规范、经纬度范围，并限制请求大小。

## 实时 3D 地球

在网络总览新增非装饰性 Three.js 地球视图，使用可识别的陆地轮廓点阵、经纬网格和当前活动路线。地球按现有实时连接 WebSocket 更新，不为每条观测创建独立、无限增长的轨迹历史。

- 起点取对应 Agent 手工经纬度；终点取远端 IP 的最终有效坐标。
- 将实时连接按 Agent + 远端 IP 聚合，并按双向速率排序，默认绘制前 100 条路线；聚合后的路线悬浮/键盘聚焦显示 Agent、域名/IP、ASN/组织、国家/城市、活动流数和上下行速率。
- 缺少起点或终点坐标的连接不画路线，并单独显示未定位连接数；完整连接仍可在实时连接页查看。
- 支持按 Agent 和可信状态筛选。筛选仅影响地球呈现，不修改采集与历史结果。
- 支持暂停/恢复动画、缩放/旋转和恢复视角。减少动态效果时停用自动旋转；WebGL 不可用、组件错误或小屏资源不足时提供明确状态并保留其他总览内容。
- 地球容器稳定尺寸、响应式适配且不遮挡同页数据。组件卸载时释放 Three.js 几何体、材质、渲染器、事件监听和动画帧；限制点数、路线数和更新频率，避免每条 WebSocket 消息重新创建整个场景。
- 陆地几何资源随 Web 构建打包，不在浏览器运行时依赖第三方地图服务。资源来源及许可随实现一并记录。

## 连接发起方

连接发起方单独于 `local_is_source`、上传/下载方向和字节计数保存。活动连接与历史 Presence 均保留角色、证据来源和可判定状态，至少区分：

- TCP：`local_initiated`、`remote_initiated`、`unknown`。
- UDP：`first_observed_local_to_remote`、`first_observed_remote_to_local`、`unknown`。界面称为“首次观察方向”，不称为握手发起方。

端点 Agent 使用不读取应用载荷的 connect/accept 生命周期观测，在 Agent 运行期间将事件与 socket/flow 关联。该能力单独报告，不等同于现有 cgroup-skb 字节计数能力。生命周期钩子、权限或内核支持不可用时，端点仍采集 socket 和流量，但角色为未知并报告降级原因。Agent 启动前已建立的连接、事件丢失、无法关联 inode/tuple 的连接一律未知；不能用端口号、字节方向或经验规则伪装为确定值。

网关保留 conntrack 原始 tuple 的起始方向。只有在已知本地网络前缀能唯一确定发起方位于被监控 LAN 还是外部网络时，才映射到“本机/LAN 发起”或“外部发起”；双端都在已知 LAN、都在外部、NAT 前后映射不完整或网段不明时显示未知。UI 同时给出判定来源/状态，避免把 conntrack tuple 的源端误解释成 Agent 主机自身。

Protobuf observation、Center domain model、实时表 `live_connections`、分钟流量与 Presence 分别增加兼容的 origin 值和证据来源字段。实时 REST/WebSocket 与历史排名均返回这些字段；`traffic_minute` 的新分钟行和 `connection_presence_minute` 的新记录携带发起方值。旧 ClickHouse 行默认 `unknown` 且 evidence 不可用，不回填、不推断。设备能力增加独立的连接发起方状态，端点未能加载生命周期钩子时只将该能力标记降级，不关闭原有 socket/字节采集。

发起方可作为实时连接与历史排名的筛选/分组维度。该维度缺失时显示“未知”，旧历史行不回填。发起方不得改变上传/下载定义、流量统计、NAT 元组和可信筛选。

## 代理报告的客户端 IP（后续）

普通 socket、conntrack、eBPF 字节计数和 HTTPS 加密流量无法读取 `X-Forwarded-For`。Lucky/CDN 可在反向代理层校验转发链后知道客户端 IP；后续通过 Lucky API 获取，不从网络包中猜测，也不在本轮开发通用访问日志采集器。

后续关联必须保留三种概念：实际 TCP 对端（例如 CDN/Lucky）、代理报告的客户端 IP、后端服务/上游 IP。只有 Lucky API 提供的来源和关联标识足以匹配时才关联到具体活动连接；否则只展示为独立代理访问元数据。该值不重写网络源/目的地址，不重复计流量或连接数。API 缺少可信代理链验证、来源标识或必要关联字段时，值需标为未验证/未关联，不用于自动信任、归属或排名。

## 24 小时排名与历史模型

总览默认展示四组榜单：

1. Agent。
2. 远端域名；没有域名时以“未知域名 · IP”区分并可追查。
3. Agent + 本地端口。
4. Agent + 进程；未知进程单独归组。

每行展示总字节、上传、下载、窗口内 distinct `flow_id` 数、估算标记和数据缺口提示。默认每组显示前 10 项，可展开至最多 50 项。共享时间窗为最近 24 小时，并有可信状态筛选。榜单支持切换到远端 IP、网卡、ASN、国家/地区/城市和容器；无数据时显示空状态，不以零值伪装缺失数据。

流量字节从现有 `traffic_minute` 取得，保留现有方向和估算语义。为新写入增加规范化 `remote_ip` 快照，使可信筛选和“未知域名 · IP”归组使用稳定的远端角色，而不猜测 source/destination。连接数从 `connection_presence_minute` 以窗口内去重的 `(device_id, flow_id)` 计算。采用兼容的 ClickHouse 增量迁移，为 Presence 增加形成排名所需的进程、容器、接口、本地端口和规范远端 IP 等维度；旧行通过默认空值保持可读，并在 UI/API 中标记历史维度不可用，禁止伪造回填。新写入同时规范本地/远端角色，避免正向/反向观察造成端口定义漂移。

排名查询先按“榜单维度值 + 设备 + 远端 IP”分别汇总流量字节和 Presence distinct flow，再由 Center 应用当前 IP 手工覆盖与可信状态并合并最终标签/桶。这样可信筛选在聚合前语义正确，手工域名可应用于历史响应而不改写 ClickHouse。域名多对一或歧义时，流量仍只计一次；歧义名称作为一个带候选值的桶展示，不将字节复制到每个域名。未识别域名使用“未知域名 · IP”桶。实现必须限制中间聚合规模、查询时长和并发；达到上限时返回明确的部分结果/降级状态，不静默返回错误总数。

新增受管理员认证保护的 `GET /api/v1/overview/rankings`，限制时间范围、维度、每组条数和查询并发；只允许白名单维度，所有过滤值参数化。响应包括时间窗、维度、值、设备标签、上下行字节、distinct flow 数、估算、数据缺口和历史维度可用状态。支持连接发起方筛选/分组。可信过滤按远端 IP 关联 PostgreSQL 覆盖表，在最终分组前生效；由于 ClickHouse 与 PostgreSQL 分开查询，Center 负责有限规模的中间结果合并并报告降级状态。

流量榜单和实时地球不新增 Prometheus 高基数标签；仅保留低基数计数、错误、查询耗时等指标。

## 控制台交互

- 点击实时连接、地球路线或排名中的 IP/域名可打开统一的归属详情面板。
- 实时连接列表独立显示发起方/首次观察方向、证据来源和未知状态；提供本地发起、远端发起、首次观察方向、未知筛选，不改变现有上传/下载列。
- 面板分开呈现“自动识别”和“手工覆盖”，包括域名/来源、ASN 组织、国家/地区/城市、坐标、可信标记和更新时间；可保存、逐字段清除并查看审计变化。
- Agent 页面现有档案编辑增加可选纬度/经度；地球视图可从坐标缺失状态引导到该档案编辑。
- Agent 名称使用当前设备自定义名称；已注册设备与 LAN 资产维度不在本次变更中扩展。
- 总览保留原有设备状态与活动连接内容，不让 WebGL 错误导致整页空白。

## 方案比较

1. **扩展现有 Center（选定）**：复用当前认证、审计、ClickHouse、PostgreSQL、WebSocket 和 Vue；只有兼容迁移与新 API，不增加容器。适合现有家庭实验室部署。
2. **新增独立分析服务**：职责隔离，但增加数据库访问、部署、认证和维护成本，不符合当前规模与 Light/Pro 简化目标。
3. **只拼接现有 API**：初始改动较少，但历史 Presence 缺少进程、本地端口等流数维度，且无法可靠提供手工 IP 覆盖和可信筛选。

## 验收标准

- IPv4/IPv6 地址规范化后，同一 IP 的手工覆盖对所有 Agent 一致生效；可逐项覆盖和清除，审计记录完整。
- TCP 连接发起方只有在 connect/accept 生命周期或 conntrack 与本地网段证据完整时分类；启动前已有连接和不确定路径显示未知。UDP 明确显示首次观察方向而非 TCP 发起方。上下行速率与发起方标签互相独立。
- DNS 名称优先于 PTR；有效 DNS TTL、多个名称歧义、PTR 成功/失败缓存、私网地址跳过、限流和查询超时均有测试。
- 手工域名、ASN 组织、地理字段覆盖自动值；原始库来源和历史分钟字节不被改写。可信只影响标记与显式筛选。
- Agent 坐标验证边界正确。地球只绘制坐标齐全的路线，最多 100 条聚合路线；WebSocket 更新、筛选、暂停、错误降级、组件卸载资源释放正常。
- 桌面和移动视口截图确认地球非空、比例合适、控件可用、内容无重叠；使用浏览器检查 WebGL 画布像素和旋转/路线交互。
- 四组排名与可切换维度的字节、方向、distinct flow 数、估算、可信筛选和发起方筛选在窗口边界及空/未知数据下正确。迁移对已有数据库可重复执行，旧记录不被重写。
- 以 10 个端点、1 个网关和 10,000 条活动连接进行总览压力验证；路线绘制上限固定，排名查询有超时/上限且不阻塞采集。
- `go test ./...`、Web 类型检查与构建、迁移/查询测试以及 Docker 镜像构建通过；Prometheus 指标无 IP、域名、设备 ID 或进程名等高基数标签。

## 不在本次范围

- 连接结束后的逐连接事件归档或历史路线回放。
- 使用外部 API 查询 ASN、GeoIP 或 PTR；向第三方发送观察 IP。
- 本轮读取 HTTP 请求头、采集通用反向代理访问日志或从 Lucky API 获取转发客户端 IP；后续设计单独评估 Lucky API 字段、可信代理链和连接关联能力。
- 自动推断 Agent 的物理地理位置、由 Center/网关位置替代 Agent 起点。
- 可信 IP 自动隐藏、排除统计或更改流量采集。
- 告警通知、跨用户权限系统、新的独立分析服务、LAN 拓扑改造。

## 已知限制与实施注意

- PTR 名称是 DNS 配置者可控的反向名称，不保证等于真实服务域名；界面必须明确标识 PTR 来源。
- GeoIP 城市坐标是近似位置；手工 Agent 坐标依赖管理员输入。
- 现有历史 Presence 记录缺少新增维度，升级后仅新数据能按进程、容器和本地端口准确计连接数。
- ClickHouse 查询复杂度与 IP/域名基数相关，排名 API 必须有时间范围、维度白名单、结果条数、超时和并发限制。
- WebGL 对旧设备或远程桌面环境可能不可用；该能力必须降级，不影响其他总览内容。
