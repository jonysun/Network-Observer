# LAN 设备拓扑与画布重构设计

## 目标与边界

修复 LAN 拓扑页完全不显示的问题，并明确数据与展示职责：ARP/NDP 观测经服务端归并、过滤后形成拓扑 API；画布只展示 API 中有证据的节点和关系。此次不改造 Agent 的 ARP/NDP 采集，不把外部连接或流量信息引入 LAN 拓扑，也不推断未经观测或人工确认的物理链路。

## 设计

1. **LAN 资产归并**：一个设备是逻辑设备，多个 MAC/IP/网卡作为可展开的网络接口呈现。Agent 主机身份和本机接口作为强归并依据；无可靠身份的邻居继续按现有 MAC/网段键识别，不按相似名称或厂商自动合并。接口属于不同网段时可在各自网段组展示同一逻辑设备的接口入口，入口链接到同一设备详情，不生成跨网段链路。
2. **拓扑划分**：同一画布容纳多个相互独立的网段/网关组。每组只包含其网段的 Agent 接口、邻居资产和已有证据支持的观察/人工确认边。Center 使用独特标识；Agent 使用独特标识，并按其接口所属网段出现。未确认归属放在明确的未分配区域。
3. **过滤**：精确排除已上报且能验证归属的 Docker 子网/bridge 资产（如匹配到已知 Docker CIDR 的 `172.17.0.1`）。不按 RFC1918 大段粗暴屏蔽，避免误删真实局域网。过滤在拓扑数据层进行，不由画布猜测。
4. **画布**：以 Vue Flow（MIT）替换自研 SVG 的视口/节点拖拽底层，使用项目自定义节点和边；保留层级/星云切换、无限平移缩放、手动拖动及布局持久化。自动布局用稳定排序和固定层级规则；恢复保存布局时校验坐标，缺失/越界时回退自动布局，避免 fit-to-view 被极端历史坐标缩至不可见。Vue Flow 负责交互和视口，不负责推断网络关系。
5. **加载与诊断**：LAN 表格与拓扑继续独立加载；API 错误、零节点、全部过滤、未分配资产均显示不同状态。接口返回的节点/边数量和过滤原因可用于诊断，避免把空白画布误当作“没有设备”。

## 兼容性

维持 `/api/v1/lan/topology` 现有基础响应字段；新增逻辑设备/接口关系字段为可选字段。旧历史快照缺少这些字段时由前端兼容回退。Center/Agent 的既有 API 和采集协议不变。布局版本递增并只在无法安全复用旧坐标时重建自动布局；手动设备及确认链路尽量保留。

## 验收

- 至少一个网段、多个网段、无数据、API 失败、全过期、全部 Docker 过滤均有正确可见状态；有效节点不会因无效/极端坐标而不可见。
- 同一 NAS 的两个已确认接口显示为一个设备的两个接口；无法确认同一设备时不误合并。
- 多网段同时显示但没有无证据跨网段边；Center 与 Agent 图标可区分；观察关系和人工确认关系可区分。
- `172.17.0.1` 仅在已知 Docker 子网证据匹配时排除；其他合法 `172.16.0.0/12` 局域网仍可显示。
- hierarchy/nebula 切换、拖动后重进保留布局；平移、滚轮/触控缩放、适应视图和键盘可用。
- Go 单元测试、前端构建、Compose 校验通过；在代表性 API fixture 上验证画布实际渲染。
