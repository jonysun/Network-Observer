# Agent 明文 TCP DNS 解析设计

## 目标与范围

在 Linux Agent 现有 AF_PACKET 观测点增加明文 TCP/53 DNS 响应解析，提取问答中的域名、A/AAAA 地址及 TTL，并复用既有 DNS 事件/WAL 链路。UDP/53 保持兼容；DoT、DoH、非观测点流量不在范围内。

## 方案

- 采用已确认的成熟方案：gopacket TCP 流重组；不手写 TCP 序号/乱序重组。
- 使用 DNS-over-TCP 两字节长度前缀逐条提取消息，拒绝不完整、超长和有序缺口后的消息。
- 对活动流、重排页、每条消息长度和空闲超时设硬上限，超限明确计入降级状态。
- 复用当前 DNS 消息解析与幂等事件上报，能力详情分开报告 UDP/TCP 捕获数和解析结果。

## 取舍

自行实现更少依赖，但重传、乱序和序号回绕风险高；只按端口解析不正确。gopacket 增加依赖与少量内存成本，因此必须配置缓冲边界并做资源上限测试。

## 验收

测试 TCP DNS 长度前缀拆分、分段/乱序重组、响应答案解析、错误/超限帧拒绝、过期流回收、UDP 回归。运行 Agent 定向 Go 测试和 `go test ./...`（若环境支持）。
